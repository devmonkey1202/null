# NULL 자유도 엔진/플러그인/운영 구현 계획

이 문서는 사용자가 요청한 기능(자유도 엔진, 플러그인 생태계, 운영 안정화)을 **순서대로 1~n**으로 분해한 실행 계획이다.
모든 항목은 **완료 체크([ ]) → 완료([x])**로만 상태를 표시한다.

## 완료 표시 규칙
- [ ] 미완료
- [x] 완료

## 1) 범위 고정 및 용어 확정 (완료)
1. 런타임 위젯 인젝터: 사용자 정의 UI 코드를 에디터 캔버스와 배포 런타임에 렌더링하는 기능을 의미한다. 위젯은 반드시 샌드박스에서 실행되며, 메인 엔진에 직접 접근할 수 없다.
2. 보안 샌드박스: 사용자 코드 실행을 격리하여 메인 스레드, 쿠키, 로컬 스토리지, 내부 객체에 대한 직접 접근을 금지한다. 통신은 메시지 브릿지로만 허용한다.
3. 백엔드 커스텀 코드 노드: 워크플로우 내에서 사용자 정의 서버 로직을 실행하는 단위이며, 입력/출력 계약과 제한된 실행 환경을 가진다. DB 직접 접근은 금지하고, 안전한 SDK 경유만 허용한다.
4. 플러그인 권한: 플러그인이 사용할 수 있는 기능 범위를 권한 스코프로 제한하며, 설치 시 명시적 동의가 필요하다. 묵시적 권한 상승은 금지한다.
5. 메시지 규약: 플러그인/샌드박스는 내부 doc/variable에 직접 접근할 수 없으며, 표준화된 JSON 이벤트로만 요청과 응답을 교환한다.
6. 플러그인 버전 관리: 배포된 버전은 불변이다. 업데이트는 새로운 버전으로만 가능하며, 앱 제작자가 수동으로 선택한다.
7. DEV/PROD 분리: 편집 환경과 운영 환경은 데이터와 라우팅이 분리되어야 한다. 운영 반영은 명시적 배포(원자적 배포)로만 가능하다.
8. 전역 상태 엔진: 앱 전역 스토어를 제공하되 기본값은 비영속이며, 워크플로우/바인딩으로만 조작한다.
9. 금지 사항: 메인 스레드에서의 사용자 코드 실행, 직접 DOM 주입, 내부 객체 직접 접근, 플러그인 무권한 네트워크 접근, 배포 없이 PROD 변경, 권한 동의 없는 설치는 금지한다.

## 2) 런타임 위젯 인젝터 설계 (완료)
1. 렌더링 레이어 구조: 캔버스(SVG) 레이어와 별도의 오버레이 DOM 레이어를 분리한다. 위젯은 오버레이 레이어에서만 마운트한다.
2. 렌더 대상 타입: 위젯 노드는 별도 타입으로 정의하며, 외부 라이브러리 컴포넌트를 마운트하는 컨테이너로만 동작한다.
3. 라이프사이클: 마운트, 업데이트, 언마운트 단계가 명확해야 하며, 문서/바인딩 변경 시 재렌더를 보장한다.
4. 크기/레이아웃: 위젯은 캔버스 노드의 프레임 크기에 종속되며, 리사이즈 시 안전하게 재배치된다.
5. 성능/리소스 한계: 위젯 수, 업데이트 빈도, 메모리 사용량은 설정 가능한 한계로 제한하며 기본 안전값을 둔다.
6. 오류 격리: 위젯 오류는 전체 렌더링을 중단하지 않는다. 오류 발생 시 대체 UI와 로그를 제공한다.
7. 보안 경계: 위젯은 오버레이 컨테이너 내부에서만 DOM 접근이 가능하며, 메인 문서 DOM에는 접근할 수 없다.

## 3) 샌드박스 실행 환경 설계 (완료)
1. 기본 격리 방식: iframe sandbox를 기본으로 사용하고, 계산형 작업은 WebWorker로 분리한다.
2. iframe sandbox 속성: `allow-scripts`만 허용하며, `allow-same-origin`은 기본 금지한다. 필요 시 별도의 프록시 도메인에서 제한적으로 허용한다.
3. 네트워크: 샌드박스는 직접 외부 네트워크 호출을 금지하고, 반드시 메시지 브릿지 요청을 통해 서버 측 프록시를 사용한다.
4. 스토리지: 로컬스토리지/쿠키 접근은 금지한다. 샌드박스 내부 상태는 메모리에서만 유지한다.
5. DOM 접근: 샌드박스는 자신이 생성한 DOM 내부에서만 동작하며, 부모 문서 DOM 접근은 금지한다.
6. 리소스 제한: 실행 시간, 메시지 처리량, 메모리 사용량 제한을 둔다. 초과 시 샌드박스는 강제 종료한다.
7. 보안 정책: CSP는 `default-src 'none'`에서 시작해 필요 항목만 명시적으로 허용한다.
8. 버전 격리: 샌드박스 런타임 자체도 버전 고정한다. 런타임 업데이트는 앱 제작자의 수동 승인 후만 반영한다.

## 4) 메시지 브릿지 규약 확정 (완료)
1. 통신 방식: `postMessage`만 사용하며, JSON 직렬화 가능한 payload만 허용한다.
2. 요청 형식: `{ "id": "uuid", "type": "REQUEST", "action": "ACTION_NAME", "payload": {...} }`
3. 응답 형식: `{ "id": "uuid", "type": "RESPONSE", "status": "ok" | "error", "payload": {...}, "error": {...} }`
4. 이벤트 형식: `{ "type": "EVENT", "event": "EVENT_NAME", "payload": {...} }`
5. 허용 액션 목록: 사전에 등록된 액션만 허용하며, 미등록 액션은 즉시 `error: "action_not_allowed"`로 거부한다.
6. 권한 스코프: 각 액션은 필요한 권한 스코프가 있으며, 설치 시 동의된 권한이 없으면 거부한다.
7. 데이터 경계: 문서/변수 접근은 반드시 브릿지 API로만 가능하며, 원본 객체를 직접 전달하지 않는다.
8. 에러 코드: `action_not_allowed`, `permission_denied`, `payload_invalid`, `rate_limited`, `timeout`, `internal_error`를 기본 정의한다.
9. 레이트 리밋: 샌드박스별 초당 요청 수 제한을 둔다. 초과 시 `rate_limited` 반환.
10. 타임아웃: 요청은 기본 3초 제한이며, 초과 시 `timeout`으로 실패 처리한다.

## 5) 위젯 인젝터 기반 코드 구조 추가 (완료)
1. 노드에 `widget` 메타를 부착할 수 있도록 문서 스키마에 `NodeWidget` 타입을 추가한다.
2. 런타임 렌더링 파이프라인에서 `widget` 메타가 있으면 `foreignObject` 기반 DOM 마운트 지점을 생성한다.
3. 기존 SVG 렌더는 유지하며, 위젯은 DOM 레이어에서만 동작하도록 분리한다.
4. 위젯 렌더는 별도 컴포넌트(`WidgetSandbox`)로 캡슐화하여 향후 브릿지/권한/로딩 정책과 분리한다.

## 6) 샌드박스 런타임 추가 (완료)
1. 샌드박스 실행은 기본적으로 iframe sandbox를 사용하고, 옵션으로 Worker 실행을 지원한다.
2. 샌드박스 속성은 allowlist 기반으로 정규화하며, 기본값은 `allow-scripts`로 고정한다.
3. 실행 시간 제한(timeout)을 적용하고, 초과 시 샌드박스를 종료하고 경고 UI로 대체한다.
4. iframe은 `src` 또는 `srcDoc` 기반으로 실행되며, 둘 다 없으면 오류로 처리한다.
5. Worker 실행은 문자열 스크립트를 Blob으로 생성해 격리 실행하고, 오류 시 종료한다.
6. 위젯 오류는 런타임 전체를 중단시키지 않으며, 해당 위젯만 격리된 상태로 실패한다.

## 7) 메시지 브릿지 구현 (완료)
1. 브릿지 메시지 스키마를 정의하고, `REQUEST/RESPONSE/EVENT` 구조를 검증한다.
2. 샌드박스는 `postMessage`로만 요청을 보낼 수 있으며, 호스트는 요청을 검증 후 응답한다.
3. 액션 허용 목록(`allowedActions`)을 적용하고, 허용되지 않은 액션은 `action_not_allowed`로 거부한다.
4. 레이트 리밋을 적용하고, 초과 시 `rate_limited` 오류로 차단한다.
5. 기본 액션 `ping`, `get_page_id`를 제공하며, 그 외는 기본 거부한다.
6. iframe은 origin 검증 후에만 응답하며, srcDoc은 `null` origin을 허용한다.

## 8) 위젯 인젝터와 샌드박스 연동 (완료)
1. 위젯 렌더는 반드시 `WidgetSandbox`를 통해서만 실행되며, DOM 직접 주입 경로는 제거한다.
2. 위젯의 실행 방식(iframe/worker)은 노드 메타에서만 지정 가능하며, 런타임이 이를 강제한다.
3. 위젯은 메인 렌더링 파이프라인과 분리된 DOM 레이어에서만 동작한다.

## 9) 런타임 위젯 로딩 정책 구현 (완료)
1. 위젯 로딩 허용 목록: `allowedHosts` 또는 `NEXT_PUBLIC_WIDGET_ALLOWED_HOSTS`에 없는 호스트는 차단한다.
2. 버전 고정: `version`이 지정된 위젯은 URL에 해당 버전이 포함되어야 하며, 불일치 시 차단한다.
3. 캐시 정책: `cachePolicy`를 지원한다.
4. `cachePolicy = no-store`이면 URL에 캐시 버스터를 추가한다.
5. `cachePolicy = immutable`이면 `version`이 필수이며, 없으면 차단한다.

## 10) 커스텀 위젯 에러 격리/복구 UX 구현 (완료)
1. 정책 위반(허용 호스트/버전/캐시 규칙)은 위젯 단위로 차단하고 오류 UI를 표시한다.
2. iframe/worker 오류를 포착해 위젯 단위 오류 UI를 표시한다.
3. 타임아웃 초과 시 위젯만 종료하고 에러 UI로 대체한다.
4. 위젯 오류는 런타임 전체 렌더를 중단시키지 않는다.

## 11) 백엔드 커스텀 코드 노드 설계 (완료)
1. 워크플로우 단계 타입: `serverless_node`.
2. 입력/출력 계약: `inputs`로 임의 JSON 입력을 받고, `responseVariable`에 결과를 기록한다.
3. 오류 처리: 실패 시 `errorVariable`에 에러를 기록하고 단계는 실패로 처리한다.
4. 제한: `timeoutMs`(100~30,000), `memoryMb`(64~1024), `code` 최대 80,000자 제한.
5. 비밀키: `secrets` 배열로 필요한 키만 명시하고, 서버에서만 주입한다.

## 12) 백엔드 실행 환경 연동 설계 (완료)
1. 실행 환경은 외부 서버리스 실행기(`SERVERLESS_EXECUTOR_URL`)에 위임한다.
2. 실행기 토큰은 `SERVERLESS_EXECUTOR_TOKEN`으로 전달한다.
3. 실행기는 격리된 V8/서버리스 환경에서 코드를 실행하며, 응답은 `{ ok, result, logs, error }` 형식이다.

## 13) 워크플로우에 Serverless Node 추가 (완료)
1. 워크플로우 스키마에 `serverless_node` 타입을 추가했다.
2. 워크플로우 실행기에 `serverless_node` 처리 로직을 추가했다.
3. 실행 결과는 기본 변수 키 `$serverless_result`에 저장된다.

## 14) Serverless Node 보안 통제 구현 (완료)
1. 코드/입력 크기 제한을 추가했다.
2. `secrets` 키는 서버에서만 로드하며, 클라이언트에는 노출되지 않는다.
3. 실행기는 환경 변수로만 지정되며, 미설정 시 실행을 거부한다.
4. 네트워크 제한은 실행기에서 강제하도록 정책(`SERVERLESS_EXECUTOR_ALLOWED_HOSTS`, `SERVERLESS_EXECUTOR_DENIED_HOSTS`)을 전달한다.

## 15) 플러그인 권한 동의 UX 설계 (완료)
1. 플러그인 설치 요청 시 권한 목록을 명시적으로 표시한다.
2. 승인/거부 2가지 흐름으로 단순화하고, 거부 시 설치를 취소한다.
3. 권한 철회는 플러그인 삭제로 처리한다(권한 유지 상태로는 실행 금지).
4. 서버는 권한 동의 없이 설치되는 것을 거부한다.

## 16) 플러그인 권한 동의 UX 구현 (완료)
1. 플러그인 설치 시 권한 동의 모달을 표시한다.
2. 동의 시에만 `consent: true`로 설치 API를 호출한다.
3. 서버는 동의가 없고 권한이 있는 플러그인은 `permission_consent_required`로 차단한다.
4. 권한 라벨을 UI에 표시하고, 설치된 플러그인의 권한을 확인할 수 있다.

## 17) 플러그인 메시지 권한 분리 적용 (완료)
1. 위젯/플러그인 메시지는 `allowedActions` 기반으로만 처리된다.
2. `actionScopes`와 `allowedScopes`를 추가하여 액션별 권한 스코프를 강제한다.
3. 권한이 없으면 `permission_denied`로 차단한다.

## 18) 플러그인 버전 고정 스토리지 설계 (완료)
1. 플러그인에 `digest`, `storeVersion`, `frozen` 메타를 부여한다.
2. 스토어 플러그인은 설치 시 `frozen: true`로 저장되고 자동 변경이 금지된다.
3. 동일 id의 플러그인 업데이트 시 digest가 달라지면 기존 frozen 버전을 유지한다.
4. 버전 고정은 `storeVersion`과 `digest`로 검증한다.

## 19) 플러그인 CDN/스토리지 연동 구현 (완료)
1. 스토어 카탈로그는 `digest`를 포함하여 해시 검증이 가능하도록 제공한다.
2. 앱에 설치된 플러그인은 `digest`를 유지하고, 변경 시 자동 대체되지 않는다.
3. 설치 메타에 `storeVersion`/`digest`를 남겨 롤백 기준점을 확보한다.

## 20) 플러그인 업데이트 수동 제어 구현 (완료)
1. 앱 레벨 정책(`manual/auto/pinned`)을 저장한다.
2. UI에서 정책을 변경할 수 있고, 서버에 `PATCH`로 반영한다.
3. `pinned` 정책에서는 고정 버전을 표시한다.

## 21) DEV/PROD 데이터 분리 설계 (완료)
1. DEV/PROD는 **PageSetting 기반 환경 모드**로 구분하며, 기본은 `dev`.
2. 데이터 스키마/레코드는 **DEV 전용 슬러그(`__dev`)**로 분리한다.
3. 비소유자(외부 사용자)는 항상 `prod` 환경으로 고정한다.
4. 배포 기준 버전은 `prod_version` 메타(PageSetting)로 고정한다.
5. PROD는 **배포된 버전/데이터만** 노출되며, DEV는 에디터/협업자만 접근한다.

## 22) DEV/PROD 분리 구현 (완료)
1. `app-env` 유틸을 추가해 환경 모드/슬러그 매핑/DEV 컬렉션 보장 로직을 제공했다.
2. 데이터 스키마 API(`/api/app/[pageId]/schema`)가 환경별 컬렉션을 읽고/쓰기한다.
3. 레코드 CRUD 및 쿼리(`/api/app/[pageId]/[model]`, `/records-filter`)가 환경별 슬러그로 분기된다.
4. 비소유자는 항상 `prod`로 강제되고, 소유자는 `env` 파라미터 또는 `app_env` 설정으로 전환 가능하다.
5. PROD/DEV 컬렉션 캐시 키와 버전 카운터가 분리되도록 슬러그를 환경별로 적용했다.

## 23) 원자적 배포 로직 구현 (완료)
1. 배포 시 `current_version`을 `prod_version` 메타로 고정하고 배포 해시를 기록한다.
2. `DEV → PROD` 데이터 복제(스키마 + 레코드)를 **트랜잭션**으로 수행한다.
3. 배포 성공 시 `deployed_at` 갱신과 함께 배포 메타(해시/복제 수)를 기록한다.

## 24) 전역 상태 관리 엔진 설계 (완료)
1. 문서 스키마에 `globalState` 배열을 추가해 전역 상태 키/타입/기본값을 정의한다.
2. 타입은 `string/number/boolean/json` 4종으로 제한한다.
3. 기본 정책은 **클라이언트 메모리 전역 스토어**이며, 새로고침 시 초기화된다(비영속).
4. 서버 동기화는 기본 비활성으로 정의한다.

## 25) 전역 상태 UI 패널 구현 (완료)
1. 우측 패널에 **전역 상태** 섹션을 추가해 키/타입/기본값을 추가/수정/삭제할 수 있게 한다.
2. 프로토타입(인터랙션) 액션에 `setGlobalState`를 추가해 전역 상태를 직접 변경할 수 있게 한다.
3. 데이터 바인딩은 런타임에서 전역 상태 값을 overrides로 병합한다.

## 26) 전역 상태 런타임 적용 (완료)
1. 런타임 플레이어에 전역 상태 스토어를 추가하고 문서 정의로 초기화한다.
2. `setGlobalState` 실행 시 타입에 맞게 값 변환을 강제한다.
3. 텍스트 토큰에 `{{state.key}}` 접근을 추가한다.
4. 동기화 정책: 클라이언트 메모리 단일 소스, 서버 동기화 없음, 충돌 처리 불필요.
